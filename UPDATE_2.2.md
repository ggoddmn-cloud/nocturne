# Nocturne 2.2 — обновление Railway

Заменить в существующем GitHub-репозитории bot.py, downloader.py, requirements.txt, cache_store.py, .gitignore, .dockerignore, .env.example (последний — только пример). Dockerfile из полного архива содержит исправленный тег denoland/deno:bin; менять рабочий Dockerfile необязательно. Реальный .env не загружать. Railway Variables сохраняются. Одна реплика, локальную копию остановить.

Опциональная авторизация: поддерживаются YOUTUBE_COOKIES_B64 и TIKTOK_COOKIES_B64 — Base64 от Netscape cookies.txt для соответствующего сервиса. Только собственные разрешённые сессии. Секреты хранить только в Railway Variables, не в GitHub. Base64 не шифрование. Временная копия удаляется после запроса. Авторизация не гарантирует доступ с облачного IP. Официальная документация: https://github.com/yt-dlp/yt-dlp/wiki/Extractors и https://github.com/yt-dlp/yt-dlp/wiki/FAQ .

/d ссылка — выбор качества; до 4 операций на пользователя, 2 одновременно глобально. Кнопки разных запросов независимы. /d --fresh ссылка — пропустить кэш. Кэш по точной ссылке и чату, хранит Telegram file_id обоих результатов 7 дней. По умолчанию SQLite в контейнере, для сохранения при деплое нужен доступный для записи Railway Volume (например /data), путь определяется автоматически. Если volume недоступен для записи, кэш отключается без остановки бота.

При отказе платформы отправить свой видеофайл в личку или ответить /d на видео в разрешённой группе. До 20 МБ для получения файла через стандартный Bot API; результат до MAX_FILE_MB. Оригинал и MP4-превью. Сторонние API не подключены. Не открывать доступ недоверенным группам: исходный загрузчик прямых/HLS ссылок не является полноценной сетевой песочницей.

Проверены синтаксис и 7 локальных тестов (без Telegram, yt-dlp и сети). Сборку Docker и живое скачивание не проверяли. Для обновления yt-dlp пересобрать образ; автоматическое обновление работающего контейнера не включено.
